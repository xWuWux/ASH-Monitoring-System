# k6 API load test

Runs authenticated load against the Docker Compose API after
`tests/performance/k6/seed.sql` has inserted 500,000 command rows, 20,000
sessions, and 50,000 file changes.

## What it covers

| Endpoint | Query |
|---|---|
| `events` | `GET /api/v1/events?limit=50` |
| `hosts` | `GET /api/v1/hosts` |
| `stats_timeline` | `GET /api/v1/stats/timeline?hours=24` |
| `stats_top_commands` | `GET /api/v1/stats/top-commands?hours=24&limit=20` |
| `sessions` | `GET /api/v1/sessions?limit=50` |

Each endpoint has its own hard threshold:

- average response time `< 200 ms`
- p95 `< 500 ms`
- failed requests `< 1%`
- checks (status 200 + JSON content type) `> 99%`

k6 exits non-zero when any threshold fails, so the CI job fails rather than
silently producing a report.

## Local run

```bash
# From the repository root, with the Compose stack already running:
docker compose -f deployments/docker/docker-compose.yml exec -T \
  -e PGPASSWORD="$ASH_DB_PASSWORD" postgres \
  psql -U ash -d ash_logs -v ON_ERROR_STOP=1 \
  < tests/performance/k6/seed.sql

mkdir -p k6-results

ASH_API_BASE_URL=http://127.0.0.1:8080 \
ASH_ADMIN_USER=admin \
ASH_ADMIN_PASS='the-generated-password' \
K6_VUS=20 K6_DURATION=60s \
k6 run --summary-export=k6-results/summary.json \
  tests/performance/k6/api-load.js
```

`ASH_ADMIN_USER`/`ASH_ADMIN_PASS` are the credentials generated by
`scripts/install.sh` or the CI environment, not the old `admin`/`admin`
defaults.

## Notes

- The API has four synchronous gunicorn workers and one PostgreSQL in this
  Compose stack. 20 VUs is a CI-sized load, not a capacity benchmark for
  thousands of users; a pre-production environment with a reverse proxy is
  required for that.
- The stack has no ingress, so 502/504 cannot be produced. The failure gate
  covers 5xx/503, timeouts, and non-JSON responses.
- `tests/performance/load_api.py` remains the small every-PR regression
  guard. This k6 test runs in the main/manual ephemeral job because it needs
  the seeded stack and ~2 minutes.
